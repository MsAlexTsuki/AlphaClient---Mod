> **Draft notice:** This policy is intended for Alpha beta builds and beta participation. It does not establish that a particular beta program, eligibility process, or feedback channel is currently active.

## 1. Purpose

Beta testing allows selected users to try pre-release Alpha software or features and report defects, compatibility issues, and usability feedback before a wider release.

Beta software may be incomplete, unstable, or subject to change. Users should not rely on a beta build as if it were a final release.

## 2. Eligibility and access

Alpha must publish the eligibility criteria, application/selection process, and access duration for each beta program.

The Alpha rank **BETA** is a separately assignable beta-tester rank directly below **The Nibbler** in the project rank hierarchy. It must be labelled **BETA**. A BETA rank assignment does not, by itself, prove that a specific build or test environment is currently available.

**Beta eligibility, assignment authority, and program access rules:** [REQUIRES ALPHA CONFIRMATION]

## 3. Tester responsibilities

Testers should:
- use the build only for the stated test purpose;
- read the build-specific notes and known issues;
- report reproducible defects with relevant version and environment details;
- distinguish observed behavior from assumptions;
- avoid sharing credentials, tokens, or unnecessary personal data in reports;
- follow the applicable Terms of Service, Acceptable Use Policy, and Community Guidelines.

Testers must not:
- exploit a test build to access accounts, data, or systems without authorization;
- intentionally disrupt shared test infrastructure;
- misrepresent a known defect as a confirmed security incident without evidence;
- publish another person's private information or confidential test data.

## 4. Stability, data loss, and compatibility

A beta build may contain defects that cause crashes, performance problems, incompatibility, or loss/corruption of local or server-side test data. Back up important data where a safe backup option exists.

Alpha must state known risks and any backup or reset behavior that testers need to understand before a test begins.

**Build-specific backup, reset, and data-loss notice:** [REQUIRES ALPHA CONFIRMATION]

## 5. Feedback and diagnostic information

A beta report may include the information a tester chooses to submit, such as build version, operating system, hardware/software context, steps to reproduce, screenshots, logs, and a description of the issue.

Do not assume that Alpha automatically collects all diagnostics. The actual telemetry and crash-reporting behavior must be disclosed in POL-002 and any applicable notice.

**Feedback channel and diagnostic collection inventory:** [REQUIRES ALPHA CONFIRMATION]

## 6. Confidentiality

A beta program may include unreleased features or material that Alpha has expressly designated confidential. Any confidentiality obligation must be clearly presented and accepted before it applies. This policy does not silently impose a separate non-disclosure agreement.

**Whether a separate NDA or restricted-disclosure program is used:** [REQUIRES ALPHA CONFIRMATION]

## 7. Changes, withdrawal, and removal from a test

Alpha may change or end a test program, replace a build, or remove access where necessary for security, stability, or program administration, subject to applicable law and any separate agreement.

The grounds, notice, and review process for removing a tester must be defined before the program is launched.

**Tester removal and appeal procedure:** [REQUIRES ALPHA CONFIRMATION]

## 8. Feedback rights

Testers retain rights they have in their own submissions. Before Alpha reuses feedback, screenshots, or other submitted material outside the purpose of handling the report, Alpha must state the relevant permission or licence clearly.

**Feedback licence and attribution rules:** [REQUIRES ALPHA CONFIRMATION]

## 9. Security issues

Do not publicly disclose an exploitable vulnerability before giving Alpha a reasonable opportunity to assess and address it. Use the official route in POL-009 once published. Do not conduct testing beyond the authorized scope.
