# Recording Studio — Alpha Client Addon

Optional general-purpose recording feature packaged in the Alpha Recording Studio addon for Alpha Client (Minecraft 1.8.9 / Forge). Alpha Client is required; Alpha Client does not require this addon.

## Included
- Recording Studio project model with local metadata persistence.
- Local project catalog with list, create and open commands (`/recordingstudio list`, `/recordingstudio create <name>`, `/recordingstudio open <project-id>`).
- Atomic timeline persistence for tracks, clips, playback speeds and timeline markers; saved projects can restore their timeline after reopening.
- Project metadata and timeline are saved from the Studio Save Project control and automatically on Studio shutdown/world unload; recording start, pause and resume also create recovery checkpoints.
- Project metadata preserves elapsed active recording time (excluding pauses) and the capture interval; active sessions checkpoint elapsed time once per second so crash recovery restores the latest saved active duration without counting application downtime.
- If recording startup cannot complete its initial project checkpoint or active-session marker, the controller stops the capture session and attempts to persist a stopped-state checkpoint, avoiding stale metadata that could look like a running session on the next launch.
- An atomic per-project active-session marker is retained while a recording is in progress and cleared only after a successful final checkpoint and completion of all accepted frame and microphone-audio writes; reopening a project with a leftover marker reports an interrupted session while preserving existing frame files.
- Stopping a session keeps its recovery marker while frame or microphone writes are pending; the marker is cleared after finalization, including through a background finalizer during Studio shutdown.
- Existing frame filenames are scanned before recording resumes so a reopened project appends frames instead of overwriting earlier captures.
- Manual recording controller and Recording Studio-owned Forge runtime.
- OBS-inspired AlphaClient workspace with a live Minecraft viewport, dedicated Scenes, Sources, Module, Audio Mixer and Controls panels, plus visible Video and Audio timeline tracks with clip positions and a recording playhead.
- Main Recording Studio workspace navigation with three selectable tabs: Recording (capture, scenes, sources and microphone controls), Editing (timeline and Review playback controls), and Publishing (MP4/GIF export controls and export status). The tabs switch the visible action groups without replacing the shared project or recorder runtime; Studio Settings remains available from every tab.
- Persisted scene management with create, rename, remove and cycle controls; the final remaining scene is protected from deletion.
- Built-in per-scene Minecraft Capture and Microphone sources with enable/disable, remove and reorder controls. Each scene can save its own microphone input-device override; older projects without a scene override continue to use the project-level microphone selection as a compatibility fallback. Select a source in the Sources panel, then move it up or down; the order is saved with the scene. Disabling or removing microphone capture stops an active microphone session. Scene selection, scene edits and Game Capture source changes are locked during active or paused recording so captured frame timing cannot silently become discontinuous.
- Module panel with Normal Gameplay and Build Timelapse choices; optional module adapters can expose additional recording workflows without adding feature-module imports to Recording Studio.
- Build Timelapse adapter exposes saved Build Timelapse camera paths in the Module panel. Selecting a path positions the shared Build Timelapse camera at its first waypoint; recording starts path playback and captures the moving camera view. Pausing and resuming the recording also pauses and resumes that path.
- Explicit microphone recording controls with selectable detected input devices or the operating-system default; the selection is saved per scene. Live microphone monitoring can mirror the active capture to the default audio output using a bounded, best-effort queue that does not block WAV recording. PCM 44.1 kHz, 16-bit mono WAV files are written on a dedicated audio thread.
- Separate Game Audio scene source and capture service. When enabled, it starts and stops with the video recording, writes its own WAV files, resumes after recording pauses and adds clips to the Audio timeline. It uses a separately selected Java Sound capture input; actual game/system audio requires an OS-provided loopback input such as Stereo Mix or a virtual audio cable.
- Completed microphone recordings are added as clips to the standalone Audio timeline track and persisted with the project.
- Stopped frame recordings are added as an editable `@capture` clip on the Video timeline track; the clip duration follows the active recording time.
- In-Studio playback of the project's captured PNG sequence, with asynchronous frame decoding, play/pause, previous/next frame controls, video-timeline seeking, a playback-synchronized timeline playhead and aspect-ratio-preserving preview; playback follows per-frame active-timeline timestamps when available and falls back to the configured capture interval for legacy frames without timestamp sidecars.
- Review playback synchronizes audio timeline clips with the video playhead, including delayed and overlapping clips. Audio is decoded and streamed on background workers rather than fully loaded into memory, and clip playback speed is applied by adjusting the output sample rate.
- Review preview can extract and display external video timeline clips at the current playhead using FFmpeg. External-only timelines can be reviewed, played, paused, stepped and sought without captured PNG frames. Frame extraction runs asynchronously, previews are capped at 1280x720 and sampled at up to 10 frames per second, and the clip's timeline speed is applied when calculating the source timestamp.
- Background MP4 and GIF export from ordered captured PNG frames, with cancellation while the Studio is open, continuation after the Studio window closes, and temporary-output cleanup; files are stored under `recordingstudio/exports/<project-id>/`.
- Video export holds the final captured frame when the overall timeline extends beyond the captured `@capture` clip, so later imported clips are not cut off when the capture sequence ends.
- YouTube-oriented export controls: Original, 1080p and 720p resolution limits (downscale only, preserve aspect ratio); MP4 High/Balanced/Smaller file quality presets; source frame rate retained; H.264 High Profile MP4 with AAC audio resampled to 48 kHz.
- Dedicated compact Recording Studio Settings workspace with category navigation, searchable setting descriptions, Basic and Advanced modes, aligned inline controls and Alpha dark-and-gold styling. User-level preferences are stored separately from project data; export resolution and quality presets persist between launches. Advanced Diagnostics exposes saved, pending, dropped and failed frame counts alongside export and runtime status.
- MP4 export includes saved Audio timeline clips, delayed to their timeline positions and mixed when multiple clips exist; GIF output is silent.
- Microphone capture is split into separate timeline clips when video recording is paused; if microphone capture was active before the pause, a new microphone clip starts automatically after video recording resumes and the previous WAV file has finished finalizing. Manually stopped microphone capture is not restarted.
- Minecraft framebuffer capture backend scheduled at the end of the HUD render pass, before the current GuiScreen is drawn, so the Recording Studio window itself is excluded from gameplay footage. When Minecraft's hide-GUI setting suppresses overlay events, capture falls back to the world-render event. OpenGL framebuffer readback runs on the client thread; the previous framebuffer binding and viewport are restored immediately, while PNG conversion and disk writes run asynchronously on a dedicated worker.
- Desktop video source captures the complete primary monitor (not only the Minecraft window) through Java AWT Robot, including other visible applications and the Recording Studio GUI. Display video source captures one selected non-primary monitor; the selected monitor ID is persisted per scene. Desktop/Display screenshots are taken after the rendered Minecraft frame so the full visible desktop is included. Scenes can combine multiple enabled visual sources; sources are composited in source-list order, with earlier sources drawn above later ones. Each visual source stores normalized position, size and crop parameters; the current source controls adjust position and size or reset the source to the full canvas.
- Bounded encoder queue (one active write plus up to eight queued frames) with a separate dropped-frame counter when the queue is full. Each successfully captured PNG receives an atomic `.time` sidecar containing its active project-timeline timestamp; timestamp metadata failures are reported without miscounting an already-written PNG as a failed frame.
- Atomic PNG file replacement so interrupted writes do not leave partially written final frame files.
- Live pending-write counter; accepted frame writes drain without blocking the Minecraft client thread during shutdown.
- REC, pause, resume, stop and save controls in the dedicated Studio screen, with a visible recording state and elapsed-time indicator.
- AlphaClient dark-and-gold styling across the main dashboard, timeline editor, camera editor and storage overview, with consistent custom buttons and panel layout.
- Storage usage overview for project metadata, captured video frames, microphone audio, game audio and exported media. Manual cleanup offers a preview-first retention period (7, 30, 90, 180 or 365 days; OFF by default) and a separate confirmation screen. It only targets old media under `recordings/` and `exports/`; active or unreadable projects are protected, and project metadata, timelines and recovery markers are never deleted. Nothing is removed automatically.
- Adjustable capture interval in 100 ms steps, bounded to 100–60000 ms.
- Separate saved, pending, dropped and failed frame counters. Queue saturation increments dropped frames; capture or disk-write errors increment failed frames, and failed writes do not inflate the saved-frame count.
- Shared general-purpose timeline, marker and clip/track models and editor.
- Visual Timeline Editor with separate media track rows; select and drag clips to reposition them, trim either edge, and add, select, drag or remove timeline markers. Marker categories include Manual, Milestone, Camera Cut, Time Change, Weather Change and Chapter. Manual millisecond-based clip controls remain available alongside visual editing.
- Non-destructive per-clip effects for imported video: None, Grayscale, Sepia, Brighten, Darken and Contrast. Effect selection is saved with the timeline and applied consistently in the Review preview and MP4/GIF export.
- Per-clip fade-in and fade-out controls for imported video clips. Fade durations are saved with the timeline and represented in both Review preview and MP4/GIF export.
- Manual transitions between adjacent imported video clips. Each clip pair has its own selected transition type and duration; supported types are Cross Dissolve, Dip to Black, Wipe Left, Wipe Right, Slide Left and Slide Right. Users explicitly add, change or remove transitions; no automatic transitions are applied. Transition settings are persisted and rendered in Review and MP4/GIF export.
- Timeline Editor media import through a file picker for common video formats (MP4, MOV, MKV, AVI, WEBM, M4V, GIF, MPEG, MPG, FLV, WMV) and audio formats (WAV, MP3, AAC, M4A, OGG, FLAC, WMA). Imported files are added to the matching Video or Audio track, appended at the current timeline end, and use FFprobe on a background worker to detect their duration without running the probe on the Minecraft client thread. If FFprobe is unavailable or cannot read the file, the selected path remains available for manual clip creation with a user-entered duration.
- Shared camera pose, modes, paths, waypoints, interpolation, presets, orbit calculations and local path persistence.
- Recording Studio-owned Minecraft render-view camera adapter. It uses an unspawned render-view entity and does not move or control the real player.
- In-game Camera Editor for activation, deactivation, position, yaw, pitch, roll, FOV and camera paths. Camera roll is applied through Forge's camera-setup event only while the Recording Studio-owned render-view camera is active.
- World-space camera marker: a gold wireframe camera body and cyan direction/frustum guide are rendered at the active camera position, including while the editor GUI is open.
- Camera paths are stored locally under the Recording Studio data directory.
- F8 keyboard shortcut to open Recording Studio while no GUI is open; the shortcut is registered as a Minecraft control and can be rebound in Controls.
- No Build Timelapse imports, build-event listeners, Supabase calls or network services inside Recording Studio.

## Current limitations
- The Build Timelapse module option is registered when BuildTimelapseRuntime starts. Closing its Studio screen releases its camera but keeps the adapter registered until the current world unloads, so Recording Studio can select it in the same world session.
- The Alpha Recording Studio Forge entry point initializes BuildTimelapseRuntime on client-world load and registers its camera-path adapter before Recording Studio opens. `/buildtimelapse` opens the separate workspace. Recording Studio can also be opened with the configurable F8 keybind when no GUI is active; a top-level Alpha Client module-menu entry is not implemented in this isolated addon branch.
- Build Timelapse camera paths remain stored under `buildtimelapse/camera-paths/`; the Recording Studio Module panel reads those saved paths. Path creation/editing remains in the Build Timelapse Camera Editor.
- If a separate Build Timelapse recording is already active, Recording Studio will not take ownership of its camera.
- The in-game marker is a debug visualization, not a full 3D camera model.
- Camera roll is applied by the Forge camera-setup event while the Studio-owned render-view camera is active; this has not yet been verified in a running Minecraft client.
- Camera path interpolation and render-thread behavior have not been compiled or tested in Minecraft.
- Minecraft Capture uses native framebuffer resolution. OpenGL framebuffer readback remains on the Minecraft client thread; PNG conversion and disk writing run asynchronously. Desktop and Display capture use the selected monitor's native bounds via AWT Robot; screen capture itself is synchronous on the render thread, while PNG encoding and disk writing remain asynchronous.
- FFmpeg must be installed separately and available as `ffmpeg` on PATH for MP4/GIF export.
- Export derives its frame rate from the capture interval (including sub-1 FPS rates) and uses the first captured frame's resolution. Video-track clip start positions, durations and playback speeds are applied to MP4 and GIF exports; the reserved `@capture` source refers to the project's captured PNG sequence, while other video clip sources must be valid video file paths. External video timeline clips can now be exported without captured PNG frames; when no captured frame is available, FFprobe reads the first external video's dimensions to establish the export canvas. FFprobe must be installed beside FFmpeg or available on PATH. A timeline containing only the reserved `@capture` source still requires captured PNG frames. Audio-track clip start positions, durations and playback speeds are applied during MP4 export; GIF output remains silent. MP4 and GIF exports report FFmpeg progress as a percentage in the Studio status line; GIF progress includes a short palette-generation stage. Export resolution can be set to Original, 1080p or 720p; resolution presets preserve the source aspect ratio and never upscale. MP4 quality presets are High (CRF 18), Balanced (CRF 21) and Smaller file (CRF 25), with High selected by default. MP4 uses H.264 High Profile and AAC audio at 48 kHz. Captured-frame timelines preserve saved per-frame timestamps with variable-frame-rate output; external-only timelines use the configured export frame rate. Export resolution and quality preferences are saved locally for the Recording Studio installation and restored when the Studio opens. Changing the capture interval between recording segments in the same project can make audio synchronization approximate; GIF output remains silent.
- In-Studio playback previews the captured Minecraft PNG sequence, synchronizes supported audio timeline clips, and displays external video clips when the Review playhead is inside them. External-only timelines can be reviewed without captured PNG frames. External video preview requires FFmpeg on PATH and is sampled at up to 10 frames per second; overlapping external clips are composited in timeline order, with later-starting clips layered above earlier clips. Per-clip effects and fade-in/fade-out controls on imported video clips are applied in the Review composite. Explicitly assigned transitions between adjacent imported video clips support Cross Dissolve, Dip to Black, Wipe Left, Wipe Right, Slide Left and Slide Right; transition selection and duration are saved per clip pair, and no transition is applied unless the user selects one. When an external video overlaps the @capture clip, the Review composite uses the captured PNG frame at the current timeline position as its base and layers active external video clips above it. Frame selection follows the configured capture interval and the sorted saved-frame sequence; dropped frames can therefore make timing approximate. Audio preview streams supported audio formats and applies the selected clip playback speed; playback still depends on an available Java Sound output line and a decodable source format. Review playback and captured-frame seeking use per-frame active-timeline timestamps when a valid `.time` sidecar exists; legacy PNGs without sidecars fall back to the configured capture interval. MP4/GIF export now reads per-frame active-timeline timestamps through an FFmpeg concat manifest and uses variable-frame-rate output for captured-frame timelines; legacy PNGs without `.time` sidecars use the configured capture interval. External-only timelines continue to use the configured export frame rate. Automatic disk retention is not included. Manual cleanup can delete only media under `recordings/` and `exports/` older than the user-selected threshold after a preview and explicit confirmation; active/unreadable projects and project metadata are protected.
- Microphone input can be selected from detected Java Sound capture devices or set explicitly to the system default per scene; an explicit system-default choice overrides the legacy project-level fallback without changing other scenes. Existing projects without a per-scene selection retain their project-level microphone selection as a fallback. The Refresh Mic control re-enumerates devices, clears an unavailable saved selection, preserves a still-valid project fallback, and otherwise switches to the system default. Live microphone monitoring is available while microphone capture is active and uses the system's default audio output. Game Audio uses a separate Java Sound capture line and device selection; it requires an OS loopback input and does not bundle native WASAPI support.
- Crash recovery is checkpoint-based: it detects an uncleanly interrupted session and preserves previously written frames. On the next project open, complete PNGs left in the frame writer's temporary-file state are validated and promoted to their final frame names; incomplete temporary images are left untouched. It still cannot reconstruct a partially written frame or microphone audio that was being captured when the process stopped. Active-time recovery typically loses up to about one second since the last checkpoint under normal tick operation; a longer client stall can increase that gap.
- Scene sources currently cover the built-in Minecraft framebuffer, full-primary-monitor Desktop capture, one selectable additional Display, microphone and Game Audio inputs. Multiple visual sources can be enabled together and are composited in scene source order; later sources are drawn above earlier ones. Audio sources remain independently selectable. Desktop/Display capture uses Java AWT Robot and runs synchronously during the render tick, so high-resolution displays or short capture intervals may affect frame time. Webcam capture requires FFmpeg on PATH and Windows DirectShow; arbitrary live media sources remain unsupported. Independent per-scene microphone, Game Audio and Display device selections are persisted. Per-clip effects and fade-in/fade-out controls are available for imported video clips; these controls are not available on the reserved @capture clip, and audio effects are not implemented.
- Recording Studio Settings currently expose only controls backed by existing functionality: capture interval, export resolution and quality, microphone selection/refresh, preference mode and runtime diagnostics. Accepted export jobs continue after the Studio window closes. While an export is running, a compact percentage HUD remains visible outside the Studio window; the HUD is hidden while the Studio window is open. Custom capture resolutions remain unavailable. Live microphone monitoring is available during active microphone capture; other advanced pipeline controls remain unavailable and are not presented as working settings.
- The addon entry point registers `/recordingstudio` and `/buildtimelapse`, and registers a configurable F8 keybind for opening Recording Studio when no GUI is active. It initializes BuildTimelapseRuntime on client-world load, registering the Build Timelapse camera-path adapter before Recording Studio opens. A top-level Alpha Client module-menu entry has not been added because that menu belongs to the separate core integration.
- This branch contains an isolated ForgeGradle build setup, but the current Recording Studio changes have not been compiled or verified in-game.
